# OSFS-MCTS

**Optimal State-Feature Selection via Monte Carlo Tree Search** — поиск оптимальных state и action для описания динамической системы в виде детерминированного графа переходов `(state, action) → next_state`.

Алгоритм перебирает гипотезы: какие колонки данных входят в state, а какие — в action, и оценивает каждую по функции reward, балансирующей предсказуемость и обобщающую способность. Поиск ведётся методом MCTS с UCB1, rollout — жадный на подвыборке, финальная валидация — на полных данных.

---

## Суть задачи

Даны последовательные данные — матрица `data` размером `N × max_idx`, где строки — моменты времени, колонки — дискретные признаки. Нужно найти разбиение колонок на:

- **State** (`S`) — колонки, описывающие состояние системы;
- **Action** (`A`) — колонки, описывающие действие;

такое, чтобы граф переходов `(state, action) → next_state` был максимально **детерминированным** (предсказуемым) и при этом **компактным** (не запоминал каждый переход индивидуально).

---

## Метрики

### `ku` — коэффициент однозначности (оценка предсказуемости)


ku = |state, action| / |state, action, next_state|

где `ku = 1` — идеальная предсказуемость, `ku → 0` — хаос.

Возвращает кортеж `(ku, norm_a, n_tr, n_a)`:
- `norm_a = |уникальных action| / (n + u)` — нормированное число различных действий;
- `n_tr` — суммарное число переходов `|sas'|`;
- `n_a` — число уникальных действий.

### `coverage` — покрытие


cov = |sas'| / N


Доля строк данных, покрытых графом переходов. Малый `cov` — обобщение (хорошо), большой `cov` — запоминание (плохо).

### `reward` — целевая функция

reward = ku - gamma_cov * cov^2 - alpha * norm_a - beta_a * |A| / max_idx

Компоненты штрафа:
- `gamma_cov * cov²` — штраф за запоминание (квадратичный, доминирует при `cov → 1`);
- `alpha * norm_a` — штраф за разнообразие действий;
- `beta_a * |A|/(max_idx)` — штраф за «широту» action-набора.

Если `cov ≥ coverage_threshold` — reward обнуляется (гипотеза отвергается).

## Алгоритм MCTS

### Дерево поиска

Каждый узел дерева соответствует гипотезе `(state_idx, action_idx)` — набору колонок, назначенных в state и action. Корень — пустая или предзаполненная гипотеза.

**Действия (расширение узла):**
- `('add_state', i)` — добавить колонку `i` в state;
- `('add_action', i)` — добавить колонку `i` в action.

Фактор ветвления: `B = 2 × max_idx` (каждую колонку можно добавить в state или action).

### UCB1

UCB1 = wins/visits  + c*sqrt(ln(parent.visits)/visits))

- Первый член — эксплуатация (средний reward узла);
- Второй — исследование (бонус за редкие посещения);
- `C` — параметр исследования (`exploration_param`).

### Цикл MCTS

Каждая итерация:

1. **Selection** — спуск от корня по `best_child` (максимальный UCB1), пока не достигнем нерасширенного узла.
2. **Expansion** — случайный выбор одного из `untried_actions`, создание дочернего узла.
3. **Simulation (rollout)** — жадное добавление колонок на подвыборке (`sub_n = min(N, 2000)`): на каждом шаге перебираются все доступные колонки, добавляются в state или action, выбирается вариант с максимальным reward. До 3 шагов жадного rollout.
4. **Backpropagation** — результат распространяется вверх по дереву: `visits += 1`, `wins += reward`.

### Достижимая глубина

D_reachable = log(T) / log(B)

Где `T` — число итераций, `B = 2 × max_idx`. При `T = 500` и `max_idx = 8`: `D_reachable ≈ 2.24`. Если ожидаемая глубина дерева больше достижимой, параметр `C` уменьшается (алгоритм становится более жадным).

## Автоанализ (`AUTO_TUNE = True`)

### Классификация колонок

Функция `analyze_data_structure` для каждой колонки вычисляет:
- **`consistency`** — доля случаев, когда следующее значение однозначно определяется текущим;
- **`autocorr`** — автокорреляция Пирсона между `data[i][col]` и `data[i+1][col]`.

Классификация:
- `autocorr > 0.3` → **STATE** (плавно меняющиеся колонки);
- `autocorr < 0.15` и `consistency > 0.15` → **ACTION** (резкие скачки);
- остальное → **NOISE**.

### Автоподбор параметров

`auto_tune` определяет:
- `C` (exploration) — через `recommend_c_formula`: если `expected_depth > D_reachable`, то `C = 1.414 × (D_reach / expected_depth)³`, иначе `C = 1.414`;
- `max_depth` — `expected_depth + 1`;
- `cov_threshold` — через `auto_coverage_threshold` на основе оценки размерности пространства состояний;
- `gamma_cov` — `0.3 / cov_threshold²`.

### Sweep-графики

При `AUTO_TUNE = True` запускается `plot_results`, которая перебирает:
- число итераций: `[10, 50, 100, 200, 500, 700]`;
- параметр `C`: `[0.01, 0.05, 0.1, c_rec, 0.3, 0.5, 1.0, 1.414, 2.0, 3.0]`;
- параметр `alpha`: `[0.1, 0.3, 0.5, 0.7, 0.9, 1.0]`.

Результаты сохраняются в `mcts_analysis.png` (6 графиков: ku/cov/reward/time по каждому параметру).

## Валидация

Поиск MCTS идёт на подвыборке (`sub_n = min(N, 2000)`) для скорости. После завершения:

1. Лучшая гипотеза валидируется на полных данных — пересчитываются `ku`, `coverage`, `reward`.
2. Топ-5 гипотез валидируются на полных данных и пересортировываются.
3. Лучшая гипотеза сравнивается с `#1` из топ-5 — если в топе оказался вариант с более высоким reward, он становится лучшим.

Это исправляет рассинхронизацию между `best_hypothesis` (фиксируется во время MCTS на подвыборке) и `validated_top` (пересчитывается на полных данных).

## Режимы работы

### `AUTO_TUNE = False` (по умолчанию)

Ручные параметры из `DEFAULT_*` констант. Автоанализ запускается только для информации (классификация колонок, оценка `D_reachable`), но не влияет на параметры поиска.

### `AUTO_TUNE = True`

1. Запускается `auto_tune` — автоанализ и расчёт `C`, `max_depth`, `cov_threshold`, `gamma_cov`.
2. Строится sweep-график (`mcts_analysis.png`).
3. Запускается финальный поиск с подобранными параметрами.

## Внутренние детали

### `custom_sort_key`

Тай-брейк при равных reward:

```python
(-ku, norm_a, -n_tr, -n_a, coverage)
```

Сначала — выше `ku`, затем — меньше `norm_a` (меньше разнообразие действий), затем — больше переходов, больше уникальных действий, меньше coverage.

### `greedy_rollout`

Используется в секции 3 (автономный rollout) и внутри MCTS (упрощённая версия, 3 шага). Последовательность:

1. Оценить текущую гипотезу на подвыборке.
2. Кандидат из автоанализа — объединить state/action из анализа с текущими.
3. Кандидат «batch» — все action-колонки из анализа + первый state.
4. Жадное добавление по одной колонке — перебрать все `(add_state, i)` и `(add_action, i)`, выбрать лучший.
5. Финальная валидация на полных данных.

### Подвыборки

| Контекст | Размер | Назначение |
|----------|--------|-----------|
| MCTS `eval_sub` | `min(N, 2000)` | Быстрая оценка узлов во время поиска |
| Rollout `eval_sub` | `min(N, 500)` | Ещё более быстрая оценка в `greedy_rollout` |
| Автоанализ | `min(N, 2000)` с шагом | Расчёт `consistency` и `autocorr` |
| `auto_coverage_threshold` | `min(N, 500)` | Оценка размерности пространств |
